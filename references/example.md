# 2 线性表

## 2.3 顺序表

顺序表是用一组地址连续的存储单元依次存储线性表的数据元素。由于逻辑上相邻的元素在物理位置上也相邻，因此可以随机存取表中任一元素，存取时间为 O(1)。（PPT P18）

> 「地址连续」是全部特性的来源：能算地址，所以能随机存取；也正因为要连续，插入删除才必须搬动元素。

在顺序表中插入元素时，需要将第 i 个位置及其之后的所有元素依次后移一位，==平均移动次数为 n/2==。（PPT P19）

> 插入的代价是 `n-i+1` 次移动，取平均得 `n/2`；所以顺序表适合读多写少的场景。推导比结论更重要。

**例（PPT P20）** 在长度为 n 的顺序表中，于第 i 个位置插入一个元素，需要移动多少个元素？

解：从第 i 个到第 n 个元素都要后移，共 `n-i+1` 个。若 i 取 1 到 n+1 等概率，则平均移动次数为 `(1/n+1)·Σ(n-i+1) = n/2`。（PPT P20）

> **补充例子（非课件内容）**
> 设表长为 5，在第 2 个位置插入：原表 `[a1,a2,a3,a4,a5]`，插入后为 `[a1,x,a2,a3,a4,a5]`，a2 到 a5 共 4 个元素后移，即 `n-i+1 = 5-2+1 = 4`。

## 2.4 链表

链表通过指针表示元素之间的逻辑关系，结点在物理位置上不必相邻，因此插入和删除只需修改指针，时间复杂度为 O(1)。（PPT P24）

> 这里的 O(1) 有个前提：**已经定位到目标位置**。定位本身仍需 O(n)，下一页才补这一点，别把它当成整个操作是 O(1)。

单链表按位置查找第 i 个结点，需要从头结点出发依次遍历，时间复杂度为 O(n)。（PPT P25）

链表的存储密度低于顺序表，因为每个结点都需要额外的指针域。存储密度 = 数据域占用的空间 / 结点占用的总空间。（PPT P27）

> 存储密度是链表的固有代价，与「省不省内存」是两件事：链表省的是搬动的开销，不是空间。
