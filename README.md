# ppt-to-notes-md

把课件（`.pptx` / `.ppt` / `.pdf`）转成一份**脱离课件也能独立读懂**的中文 Markdown 复习笔记。

为 Typora 设计：课件原文白底直写，整理者的解释灰底加注，重点概念 `==黄色高亮==`，关键插图从原页自动裁切并编号，每段都标 PPT 页码。

这不是一个「一键总结」工具。它约束的恰恰是 AI 最容易失控的地方——改写原文、编造内容、只说"详见某页"、把表格搞散架。

---

## 你是否还在因为这些事而烦恼

**你是否还在因为**——让 AI 整理完课件，打开笔记发现满屏都是「详见第 23 页」「如上图所示」「同页右侧的示意图给出了……」这类话。整段笔记没有一个字是实际内容，你还得把 PPT 重新打开，一页页翻回去找？

**你是否还在因为**——课件里那张横平竖直的三阶段对比表，转成笔记后变成一堆竖线，`| 分类 | 比较项 | 人工管理 |` 整整齐齐排在那里，就是不成表？

**你是否还在因为**——笔记里分不清哪句是老师说的、哪句是 AI 加的。它把"方便随机存取"这种自己的理解写进了引文里，你复习时把它当成了课件原话背下来？

**你是否还在因为**——只想要一句解释，它洋洋洒洒写了三段，讲的全是课件上没有的背景知识。你花了十分钟判断哪些能信、哪些得删？

**你是否还在因为**——笔记的内容顺序和课件对不上，想回查某个定义出自哪一页，只能凭记忆从头翻？

**你是否还在因为**——课件里那张流程图，AI 用 `a --> b --> c` 给你画了一遍，箭头歪歪扭扭，还不如直接截图？

**你是否还在因为**——一百多页的课件，笔记写成了同样长的一篇散文，重点全淹没在铺垫里，考前根本不知道看哪里？

**你是否还在因为**——这次生成的笔记是灰底原文配白底解释，下次换一份课件就反了过来，几章笔记拼在一起像三个人写的？

## 它做了什么不同的事

三条原则贯穿全部规则：

**一、原文优先。** 定义、结论、例题的题目文字逐字照抄，不做同义替换。「互不相交的有限集合」不能写成「不相交的集合」——考试按原话给分，改写等于制造失分点。改动只允许发生在格式层：项目符号转 `-`、表格转 Markdown 表格、公式转 LaTeX。

**二、独立可读。** 笔记里不允许出现「只有指路、没有内容」的句子。凡是提到某个知识点，那个知识点的内容就必须同时出现在笔记里。页码只作为溯源标记，不承担传递信息的职责。

**三、详略可控。** 按可判定的三档处理：L1 核心（含定义/公式/定理/例题）完整保留并解释，L2 支撑（纯要点罗列）保留要点、最多两句话，L3 背景（目录页/致谢页/过渡页）不写。外加字数护栏：全文字数不超过课件的 130%，解释的字数不超过原文。

## 关键设计：标解释，不标原文

常见的做法是给课件原文加引用块，显得"这是引文"。实践下来是反的——原文占八成长度，全裹上灰底整页发闷，读者也看不出哪里该停下来细看。

| 内容 | 写法 | 在 Typora 里的样子 |
|---|---|---|
| 课件原文 | 普通段落 | 白底正体 |
| 你的解释 | 行首 `>` 引用块 | 灰底 + 左侧竖线 |
| 重点概念 | `==概念==`，写在原文段落里 | 黄色背景高亮 |
| 课件原有例题 | 普通段落，首行 `**例（PPT P12）**` | 白底，带例标 |
| 自己补的例子 | 引用块内，首行 `**补充例子（非课件内容）**` | 灰底，明确标注非原文 |

判断标准只剩一句话：**凡灰底皆解释，白底皆是课件原文。** 一页里灰块越少，说明这份笔记越没有加戏。

## 效果对照

**表格**

```markdown
✗ 原表被塞进引用块，Typora 不渲染，读者看到的是：
> | 分类 | 比较项 | 人工管理 | 文件系统 |
> |---|---|---|---|
> | 背景 | 应用背景 | 科学计算 | 科学计算、管理 |

✓ 表格回到正文层，来源由题注声明：
**表1.1 三个阶段的数据管理特点对比（PPT P4）**

| 分类 | 比较项 | 人工管理 | 文件系统 |
|---|---|---|---|
| 背景 | 应用背景 | 科学计算 | 科学计算、管理 |
| 背景 | 硬件背景 | 无直接存取存储设备 | 磁盘、磁鼓 |
```

原表第一列是纵向合并的，笔记里每一行都补齐「背景」——Markdown 表格没有合并单元格，留空读者只能靠猜。

**指引**

```markdown
✗ 同页右侧的示意图给出了这些缺点的来源：

✓ 这三个缺点来自同一个原因：数据由应用程序各自管理，同一份数据在多处重复存放，
  任何一处修改都不会同步到其它副本。
```

**原文与解释**

```markdown
顺序表是用一组地址连续的存储单元依次存储线性表的数据元素。（PPT P18）

> 「地址连续」是全部特性的来源：能算地址，所以能随机存取；也正因为要连续，
> 插入删除才必须搬动元素。
```

## 五个帮你干脏活的脚本

排版规则写在 `SKILL.md` 里由模型执行，但有几件事不能交给模型目测——它们交给确定性脚本：

| 脚本 | 作用 | 为什么需要脚本 |
|---|---|---|
| `extract.py` | 抽取每页的标题、正文层级、表格、图片数、演讲者备注、字符数，输出 JSON | 笔记里的原文必须取自这份 JSON，不能凭印象复述 |
| `render_pages.py` | 把每页渲染成 PNG（pptx 走 PowerPoint COM，pdf 走 pymupdf） | 插图要从真实页面裁，不是重新画 |
| `figure_boxes.py` | 从 PPT 形状坐标算出图的精确像素框 | 只按图像墨迹找边界，会把页面标题一起框进去 |
| `crop_figure.py` | 按框裁图；拿不到坐标时退回墨迹模式，四轮扩边仍不合格就回退整页 | 宁可带页面边框，也不把图切残 |
| `verify_notes.py` | 23 条机检规则，交付前跑一遍 | 靠提示词守规则，跑几次就会漂 |

`figure_boxes.py` 这一环是必须的。开发时实测过同一张图文页：墨迹模式裁出来是 958×756，页面标题「2.4 链表结点的指针关系」和底部说明文字全被裹进图里；改用形状坐标裁，得到 876×509，只有图本身。

## 交付前自检

`verify_notes.py` 覆盖 23 条规则，其中这些是最容易踩的：

| 检查项 | 判定 |
|---|---|
| 表格被放进引用块 | FAIL（Typora 不渲染，整表退化成竖线） |
| `==` 高亮未闭合 | FAIL |
| LaTeX 命令落在 `$...$` 外面 | FAIL（Typora 会原样显示成 `\frac`） |
| 出现乱码（`锟斤拷` / `�`） | FAIL |
| 用框线字符、ASCII 箭头、Mermaid 画流程图 | FAIL |
| 图片路径不存在 | FAIL |
| 文首缺来源/总页数/页码基准 | FAIL |
| 总字数超过课件 130% | FAIL |
| 「详见第 N 页」「同页右侧」「见右图」这类指路 | WARN |
| 表格上方没有题注 | WARN |
| 截图下一行没有图注 | WARN |
| 解释字数明显多于原文 | WARN |

`FAIL` 必须修到 0 才算完成，`WARN` 逐条人工确认。

## 快速开始

**装进 WorkBuddy / Claude Code**（任何支持 `SKILL.md` 的 agent 都行）：

```bash
git clone <this-repo> ~/.workbuddy/skills/ppt-to-notes-md
# Claude Code 用户放到 ~/.claude/skills/ppt-to-notes-md
```

之后直接扔课件、说「做笔记」即可。

**手动跑流程**（不想用 agent 驱动时）：

```bash
# 1. 抽结构
python scripts/extract.py "第4章.pptx" -o _ppt2notes_tmp/slides.json

# 2. 渲染每页
python scripts/render_pages.py "第4章.pptx" -o _ppt2notes_tmp/pages

# 3. 定位某一页的图
python scripts/figure_boxes.py "第4章.pptx" --page 13 --width 1600

# 4. 裁图
python scripts/crop_figure.py _ppt2notes_tmp/pages/p013.png \
       -o notes/img/第4章-notes-图1.1.png --box 264,264,1104,737

# 5. 自检
python scripts/verify_notes.py notes/第4章-notes.md --slides _ppt2notes_tmp/slides.json
```

**依赖**：

```
Python 3.9+
python-pptx    # 读 .pptx
pymupdf        # 读 .pdf、渲染 PDF 页
Pillow         # 裁图
pywin32        # 仅 Windows 需要，走 PowerPoint COM 导出幻灯片
```

`.pptx` / `.ppt` 的渲染依赖本机装 PowerPoint（Windows）。只处理 PDF 时不需要，可在任意平台运行。

## 产物结构

```
notes/
├── 第4章-notes.md
└── img/
    ├── 第4章-notes-图1.1.png
    └── 第4章-notes-图1.2.png
_ppt2notes_tmp/          # 中间产物，交付前删除
```

`img/` 扁平存放，靠「笔记名-图X.Y」前缀区分不同章节。图号 X 对应笔记里二级标题的序号。

## 已知限制

- **只处理有文本层的课件。** 扫描版 PDF、整页是图片的课件会直接报错停下，不会硬猜内容。需要先 OCR。
- **`.pptx` 转图依赖 Windows + PowerPoint。** 没有 PowerPoint 时只能走 PDF 路线。
- **合并单元格靠人工补齐。** 脚本能读到表格文本，但纵向合并的归属关系需要在写笔记时补到每一行，没有自动还原。
- **不会自己画图。** 课件里没有的流程图，它只会用文字分步骤描述，不会生成矢量图。
- **这是一份个人自用工具。** 规则是从我自己踩过的坑里长出来的，不是通用产品。遇到没覆盖的课件版式，需要回来改规则。
